# Sentinel QC — Content Quality Control Platform

A dual-engine quality-control tool for competitive-exam content teams. Upload a
paper (PDF / TXT / JSON / CSV), and it audits every question for **answer-key
integrity, wording clarity, distractor strength, difficulty calibration and
syllabus alignment**, then flags anything that needs a human reviewer. It also
detects whether submitted content was **written by a human or generated by AI**.

This is a QC console for the content team — not a study aid for students.

## How it works

Every content **vertical** (CLAT, CA, Design, or any you create) owns its **own
model**:

- **Gemini** — real per-vertical *supervised fine-tuning* on Google **Vertex AI**.
  Approved content becomes training pairs; the resulting tuned model audits that
  vertical.
- **Claude** — per-vertical *retrieval-augmented adaptation*. Approved content
  becomes an exemplar store that is retrieved and injected into every prompt, so
  Claude's judgement is calibrated to that vertical's gold standard.
- **Ensemble** — both engines run in parallel and a reconciler merges their
  scores, takes a majority vote on the correct answer, unions defect flags, and
  **surfaces disagreement as a "needs review" signal**. Two independent engines
  cross-checking each other is what raises accuracy.

> **Why two mechanisms?** Anthropic does not expose fine-tuning of Claude through
> its API, so Claude "learns" per vertical via RAG rather than weight training.
> Gemini is genuinely fine-tuned on Vertex AI. Both improve as the team uploads
> more approved data.

Nothing is faked: with no credentials the tool still runs **deterministic
structural + answer-key checks** and **heuristic AI-detection**, and it layers in
LLM engines as you add keys.

## Architecture

```
├── src/                 React + Vite frontend (the QC console)
│   ├── api.js           API client (calls /api, proxied to the backend)
│   ├── App.jsx          Shell, navigation, global data
│   └── components/      Dashboard, AnalyzeView, DetectorView, ModelsView, …
└── server/              Node + Express backend
    └── src/
        ├── services/
        │   ├── pdf.js         coordinate-aware PDF text extraction (pdfjs-dist)
        │   ├── parse.js       PDF/TXT/JSON/CSV → canonical questions
        │   ├── gemini.js      Vertex tuned-model inference + real tuning pipeline
        │   ├── claude.js      Anthropic inference (RAG-adapted)
        │   ├── ragStore.js    per-vertical exemplar store + retrieval
        │   ├── embeddings.js  Gemini embeddings (+ lexical fallback)
        │   ├── heuristics.js  structural QC + AI-detection heuristics
        │   ├── ensemble.js    runs engines and reconciles verdicts
        │   ├── tuning.js       Vertex supervised fine-tuning orchestration
        │   ├── registry.js    exams / model registry
        │   └── analyze.js     document-level orchestration + aggregation
        └── routes/            HTTP API
```

## Running locally

Two processes: the backend API and the Vite frontend.

**1. Backend**
```bash
cd server
npm install
cp .env.example .env      # optional — fill in keys you have
npm run dev               # http://localhost:8787
```

**2. Frontend** (in a second terminal, from the project root)
```bash
npm install
npm run dev               # http://localhost:5188
```

Open http://localhost:5188. The frontend proxies `/api` to the backend, so there
is no CORS setup. The app is fully usable with **no keys** (structural + heuristic
mode); add credentials to unlock the LLM engines.

## Configuration (`server/.env`)

Everything is optional and layered — add only what you have.

| Variable | Enables |
| --- | --- |
| `ANTHROPIC_API_KEY` | Claude analysis + detection engine |
| `GEMINI_API_KEY` | Gemini inference, embeddings (RAG retrieval), detection |
| `GCP_PROJECT_ID` + `GOOGLE_APPLICATION_CREDENTIALS` + `GCS_BUCKET` | **Real** Vertex AI fine-tuning |
| `CLAUDE_MODEL`, `GEMINI_MODEL`, `VERTEX_TUNE_BASE_MODEL` | Override model ids |

The service account needs the **Vertex AI User** role and object-admin on the
bucket. Live status for every engine is shown on the **Settings** page.

## Training a vertical

1. **Models & Training** → pick or create a vertical.
2. **Training data** → upload approved (or rejected) papers. They are parsed into
   labelled exemplars — immediately usable by Claude's RAG engine.
3. **Fine-tuning** → *Launch tuning*. With Vertex configured this starts a real
   supervised job (poll it for status); without, the job is **queued** and
   activates automatically once credentials are added.

## API

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/system` | Engine capabilities |
| `GET/POST` | `/api/exams` | List / create verticals |
| `PUT/DELETE` | `/api/exams/:id` | Update / delete a vertical |
| `POST` | `/api/exams/:id/exemplars/upload` | Add training data (file) |
| `POST` | `/api/exams/:id/tune` | Launch fine-tuning |
| `GET` | `/api/exams/:id/jobs` | Tuning job history |
| `POST` | `/api/parse` | Parse a file → questions (preview) |
| `POST` | `/api/analyze` | Full QC audit of a file or questions |
| `GET` | `/api/analyses` | Recent analyses |
| `POST` | `/api/detect` | AI-vs-human detection on text |

## Notes

- Data persists to `server/data/*.json` (a simple file store, swappable for a DB).
- The frontend bundle includes ECharts and is large; code-split if bundle size
  matters for your deployment.
